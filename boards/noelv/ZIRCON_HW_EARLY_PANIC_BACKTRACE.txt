TWO BUGS:
  A. platform_specific_halt's Backtrace::Print dereferences
     kBootConstants.kernel_debug_ident (a kPermanent PhysHandoffString) whose
     pointer is unmapped in the kernel address space -> the backtrace printer
     itself page-faults -> every panic recurses forever -> TOTAL console
     silence (this is why nothing ever printed).  NOTE kernel_version_ident
     .get() WORKED earlier (version string is in the dlog), so only some
     permanent-handoff string pointers are bad.
  B. An original panic in early PMM arena setup (PmmNode::InitArena ->
     PmmArena::Init), reason masked by the recursion.

Both smell like the experimental early-boot/memory changes on the
cocoapuffs-apbuart branch (fuchsia commit 5341d6cd: arch-allocation.h,
zbi-memory.cc, kArchAllocationMinAddr=1MiB) leaving phys-handoff pointers
unmapped.  Fix A first (so the real panic B prints), or catch B with a
hardware load-watchpoint at the fault address.

NOTE: "console silent" was a SYMPTOM — the kernel crashes in early init,
before the UART is ever set up.  The loader chain + kernel entry + PMM init
all work on HW (the cache-enable fix, PR #164).
